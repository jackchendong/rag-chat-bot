# 实现收尾审查

## 完整范围

对照原始需求审查所有任务相关文件，包括 Git 未跟踪的新文件。`git diff` 不包含未跟踪内容，先结合 `git status --short` 获取真实范围，保留用户已有改动。

## 按语义选择深度

- 拼写、排版和无行为变化的注释：检查内容及格式，不运行应用全套测试。
- 局部行为或接口说明变更：检查调用方、失败分支及聚焦测试，普通文档也可能改变使用契约。
- 凭据、敏感数据、并发取消、资源所有权、持久化或协议变更：追踪实际生产者和消费者，验证故障窗口，按需读取专项技能。

独立审查仅在用户明确要求或任务风险需要且环境提供能力时进行。提供原始需求、任务路径、完整新文件内容、关键契约和已运行检查，不预设审查结论。不要求审查者编辑、递归委派或重复运行重型检查。

## 判定与收尾

- 只提出能以代码、契约或可复现行为证明的行动项，区分真实缺陷、尚未实现的能力和无证据的风格偏好。
- 检查是否误把模型文本当作任务保存成功、把取消当作外部操作未发生、把本地锁当作跨进程保证。
- 修复后重新检查受影响边界，依据最终内容运行 [改动验证](../code-change-verification/SKILL.md)。后续行为变化不能沿用旧内容的测试或审查通过结果。
- 相同内容已通过的聚焦检查可以复用；不为重复展示证据运行相同重型命令。
- 报告需求覆盖、实际验证、未解决问题和独立审查是否执行。没有独立审查能力时明确说明，不能称自查为独立通过。
