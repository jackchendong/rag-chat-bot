# 前端项目概览

本目录是大模型对话 Demo 的前端模块，负责普通对话、定时任务确认、任务状态与执行结果展示。模型调用、任务持久化和定时调度由 `../app/` 后端负责。

当前为 Vue 3 + TypeScript + Vite 应用，包管理器为 pnpm，样式使用 Tailwind CSS。已有账号登录、退出、左侧历史会话、纯文本多轮 SSE 聊天与停止生成。已配置 shadcn-vue 的 `components.json`、主题变量和 `src/lib/utils.ts`，尚未添加库组件或定时任务功能。

本文件适用于 `front/` 及其子目录。修改前先检查实际文件、`package.json`、锁文件和更深层规范，保持已有实现，不要把计划中的目录、接口或依赖当作现成能力。

## 目录约定

按需创建，不为凑齐结构添加空文件：

- `src/components/ui/`：shadcn-vue 基础组件。
- `src/components/`：可复用的聊天、任务等业务组件。
- `src/pages/`：页面级组件。
- `src/composables/`：可复用的 Vue 组合式逻辑。
- `src/services/`：后端 API 请求及传输层适配。
- `src/types/`：共享接口、消息和任务类型。
- `src/stores/`：确需跨页面共享的状态；采用 Pinia 前先确认依赖。
- `src/utils/`：通用工具函数。
- `src/lib/`：组件库集成工具，包含 shadcn-vue 配置引用的类名合并函数。
- `src/assets/`、`public/`：分别存放构建处理资源和固定公共路径资源。
- `tests/`：已有测试体系下的测试，按实际配置组织。

## Vue 与代码风格

- 使用 Composition API 和 `<script setup lang="ts">`，业务代码使用 TypeScript。
- Props、Emits、API 响应和共享状态定义明确类型；避免 `any`，未知输入使用 `unknown` 并校验。
- 默认使用 2 空格缩进、单引号、不写分号；如项目已有格式化配置，以配置为准。
- 组件文件使用 PascalCase，函数和变量使用 camelCase，名称表达业务含义。
- 派生状态优先使用 `computed`，不要通过 `watch` 同步本可计算的数据。
- 复杂模板逻辑提取为具名函数或计算属性，组件保持单一职责。
- 请求、订阅、轮询和事件监听应在组件卸载或会话切换时清理，避免旧响应覆盖新会话。
- 不为单处简单逻辑引入复杂抽象，不保留未使用的代码和依赖。

## 依赖与工具

- 统一使用 pnpm，保留 `pnpm-lock.yaml`，不混用 npm、yarn 锁文件。
- 添加依赖时同步更新清单和锁文件；未安装的库不能直接导入。
- 日期、时间和时区业务处理优先统一使用 dayjs，仅注册实际使用的插件；不要手写时区偏移。
- 通用数据处理优先使用清晰的原生能力或已有工具。确需 lodash 时按函数子路径导入，不整体导入，也不为简单逻辑额外安装。
- 不手动修改 `node_modules/`、`dist/` 或其他生成产物。

## 样式与交互

- 使用 Tailwind CSS 和适配 Vue 的 shadcn-vue，先检查已有基础组件和业务组件，再新增。
- 不复制 React shadcn/ui 的 TSX、hooks、`className` 或 Base UI 迁移代码；组件能力以本项目安装版本为准。
- 优先使用组件变体、语义主题令牌和现有类名合并工具，避免重复颜色、任意值及大段组件内 CSS。
- Tailwind 类名应可静态识别，避免动态拼接不完整类名。
- 采用移动端优先的响应式布局，检查手机、平板和桌面下的消息区、输入框、任务列表及弹窗。
- 长文本、代码块和表格不能撑破布局；聊天输入区不能遮挡最后一条消息。
- 输入控件提供标签，图标按钮提供可访问名称，弹窗提供标题，支持键盘操作与合理焦点管理。
- 界面明确区分加载、空数据、成功、失败和离线状态，不用静态演示数据伪装真实结果。

## 聊天与定时任务边界

- API 调用集中在 `src/services/`，接口路径、字段、状态值和流式协议以实际后端契约为准。
- 登录状态只保存 account 和 user_id；退出清除这两个本地字段，不删除数据库用户和历史。API 使用 X-User-Id，聊天使用 conversation_id；这是无密码 Demo 身份识别，不承诺安全认证。
- 开发服务器通过 /api 代理后端；生产构建使用 /static/ 资源路径。pnpm build:backend 将产物写入 app/static，不修改后端秘密或迁移。
- 前端不保存模型服务密钥，不直接请求需要私密凭据的模型服务；`VITE_*` 配置会暴露给浏览器，不能承载秘密。
- 消息至少区分角色和发送状态；请求失败保留用户输入，并提供符合接口能力的重试方式。
- 如支持流式回复，应处理取消、结束、断连和重复事件；不假设后端已提供 SSE 或 WebSocket。
- 中文输入法组合输入期间不要把 Enter 当作发送；换行和发送行为保持明确。
- 用户主动向上阅读时不强制滚动到底部；持续跟随回复仅用于用户已接近底部的情况。
- 模型回复和任务结果是不可信内容，不将其直接传入 `v-html`；需要富文本时采用安全渲染并过滤危险链接。
- 创建任务前展示待确认的任务内容、执行时间、频率和时区；缺失或模糊信息交由后端澄清。
- 后端确认保存成功后才能显示“已创建”，不得把模型生成的文本当作任务创建凭证。
- 页面上的定时器只用于刷新和展示，不能承担后台调度；页面关闭后任务由后端继续执行。
- 任务状态、下一次执行时间和执行结果以服务端为准，明确标注展示时区，避免把本地缓存当作最新状态。
- 不主动扩展 RAG、文件上传、通知渠道或任务删除等尚未约定的功能。

## 本地技能

技能存放在 `.agents/skills/`，按任务选择读取，不必每次全部加载：

- `shadcn-vue`：新增、调整或修复 Tailwind / shadcn-vue 界面时，读取 `.agents/skills/shadcn-vue/SKILL.md`。
- `chat-task-ui`：开发聊天消息、流式回复、任务确认与结果展示时，读取 `.agents/skills/chat-task-ui/SKILL.md`。

这些技能只约束前端工作，不要求安装外部技能、创建分支、提交代码或发布服务。

## 验证与常用命令

所有前端命令在 `front/` 中执行。先确认 `package.json` 和实际脚本存在：

- `pnpm install`：应用初始化后安装依赖。
- `pnpm dev`：仅在配置 `dev` 脚本后启动开发服务。
- `pnpm build`：仅在配置 `build` 脚本后执行构建；确认它是否包含类型检查，必要时执行项目已有的独立类型检查脚本。
- `pnpm preview`：仅在配置 `preview` 脚本后预览构建结果。

应用代码改动完成后运行可用的类型检查和构建，以及与改动相关的现有测试、lint。纯文档改动检查格式和引用路径即可。没有应用或脚本时明确说明无法执行，不编造成功结果，也不为文档任务安装依赖。
