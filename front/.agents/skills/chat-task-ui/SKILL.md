# 聊天与定时任务前端

## 契约优先

先阅读 `front/AGENTS.md`，检查现有消息类型、请求层和后端接口。识别哪些能力已实现，哪些只是计划。不要自行承诺接口路径、流式协议、任务状态枚举或通知渠道。

若任务要求先做界面且后端尚未实现，可以使用明确标识的 mock，并保持真实请求与 mock 隔离；在交付中说明未联调部分。

## 消息流程

- 根据实际契约建模消息 ID、会话归属、角色、内容和发送状态，避免以数组位置识别消息。
- 发送时处理空内容、重复提交和输入法组合输入；失败保留可重试的信息，不误报成功。
- 请求和状态归属当前会话。切换会话或卸载时清理资源，防止迟到回复污染新会话。
- 后端支持流式响应时，按其实际分帧格式解析，不假设一个网络分块等于一个完整事件；区分结束、取消和错误。
- 取消和重试不能让旧流继续写入新回复。重试是否新建消息或复用请求标识，以后端约定为准。
- 自动滚动只在用户接近底部时跟随；向上阅读时保留位置，并提供查看新消息的入口。
- 模型内容不得直接作为 HTML 执行；代码块是展示内容，不自动运行。

## 任务确认与展示

- 区分模型提出的任务草稿与后端已保存的任务。只有创建接口成功并返回契约规定的确认信息后，才显示创建成功。
- 确认界面展示任务内容、一次性或周期性执行方式、执行时间和时区；不自行猜测“明早”等模糊时间。
- 时间计算与显示复用项目日期工具。保留服务端时间语义，不无声地转换成浏览器本地时区。
- 创建失败保留草稿，允许用户修正；避免重复点击造成重复任务，重试的幂等处理遵循实际接口能力。
- 任务列表与详情展示服务端状态和结果。未知状态提供兜底，不把请求失败解释为没有任务。
- 定时刷新或订阅仅更新界面，卸载时清理；后台执行由后端负责，不使用浏览器定时器模拟真实调度。

## 验证重点

有现成测试体系时覆盖相关行为：发送失败、会话切换、取消后迟到响应，以及任务确认、时区展示和创建失败。流式接口存在时增加跨分块解析验证。

可运行时手动检查中文输入法、多行输入、长回复、滚动阅读和任务结果刷新。按实际脚本执行类型检查和构建；记录未实现的接口和未执行的检查，不为这项前端工作扩展后端功能。
