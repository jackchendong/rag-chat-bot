# Python 后端设计

## 模块与依赖

- 从真实调用链识别职责，保持请求适配、业务决策、外部 I/O 的边界；有稳定职责后再拆分，不预建 repository、service、manager 等空壳。
- 依赖显式传入需要的边界，配置、模型客户端、存储和时钟不通过隐藏全局单例获取；简单无状态函数无需依赖容器。
- 模块导入只定义类型和行为，应用入口统一装配运行资源。客户端、线程池和调度器明确创建者、关闭者及共享范围。
- 避免循环导入，先调整职责方向，再决定是否抽取共享类型；不要通过函数内部导入或修改 sys.path 普遍掩盖设计问题。
- 值对象负责内部不变量，外部协议结构负责序列化；需要分离时显式映射，不把数据库对象直接暴露给前端。

## 配置与错误

- 配置在启动边界加载和校验，默认值与合法零值分开；模块内不散落读取环境变量和机器路径。
- 必需配置缺失时明确失败。配置对象、日志和异常不能泄露 API 密钥，开发环境默认值不能悄悄启用真实付费调用。
- 只为调用方需要分支处理的情况定义稳定领域错误，HTTP 或框架错误由入口映射，内部服务不与具体 Web 异常绑定。
- 明确可重试、不可重试和结果不确定的错误；重试策略与副作用契约关联，不对所有异常统一无限重试。
- 一次失败只在合适边界记录完整诊断，避免各层重复日志；提供安全的用户信息并保留内部原因。

## API 与输入安全

- 输入边界校验长度、范围、时间与允许值；限制消息大小、历史窗口和任务结果大小，不允许无界资源消耗。
- 用户和模型内容只产生经过校验的任务数据，执行器仅选择已注册的任务类型，不动态加载用户指定函数或任意模块。
- 若功能涉及用户指定 URL，另行检查 SSRF 与目标限制；涉及存储查询时使用参数绑定，不把输入拼接为查询语句。
- API 成功语义与实际提交状态一致。跨存储和外部系统没有原子性时说明失败窗口，不用单个 try/except 假装事务。
- 修改字段、状态、时间格式或重试行为时检查前端调用和 README，不将内部重构变成无意的破坏性契约变更。

本技能不指定框架、数据库或部署方案。设计取舍应服务当前 Demo 的真实需求，不提前承诺分布式或生产级能力。
