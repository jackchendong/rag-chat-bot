# 实现策略

## 范围契约

在现有工作说明中确认以下信息，简单改动用一段话即可，不单独创建交付文档：

- 必需行为：本次用户可观察的成功条件。
- 保持兼容的边界：已有接口、配置、持久化数据和调用方行为；没有已发布版本时不虚构发布兼容基线。
- 不支持的邻近情况：哪些输入或行为应明确拒绝，而不是自动扩展实现。
- 已有替代能力：能否通过当前组件、适配层或配置完成；没有则明确没有，不投机添加通用解析器。

## 选择实现

- 查看最近的真实调用链，复用现有校验、类型、时间处理和执行通道，避免形成两个数据或行为来源。
- 优先最小完整行为切片；必须原子改变的协议或存储契约，不为了切片制造中间不一致状态。
- 新增抽象前做删除判断：移除它是让必要复杂度散落各处，还是让不必要的复杂度直接消失？只有前者通常值得保留。
- 兼容层需要用户依赖、接口文档、测试或持久化证据，不能因为 Python 能表示某种对象就承诺支持所有对象形态。
- 重复问题需要不断新增特殊条件时，重新审视根因与范围，而不是无界叠加补丁。
- 未知的框架、协议或库行为先查真实实现和对应版本的官方资料，不凭经验补出 API。

## 验收选择

确定受影响调用方、失败窗口及最小验证。涉及取消、敏感数据或持久化时额外检查对应边界；不因此自动启用生产审计、外部付费调用或发布流程。

需求、支持范围或实现方向发生实质变化时更新范围说明，否则复用已确认信息，不重复规划。
