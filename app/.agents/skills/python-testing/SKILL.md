# Python 行为测试

- 先确认已有框架、配置、测试目录和运行方式，沿用现有模式；没有测试体系时，只在任务明确需要建立测试时选择工具，不为文档维护新增框架。
- 测试输入输出、错误分类和业务不变量，不锁定内部方法调用顺序或实现细节。
- 模型请求默认使用可控替身，不消耗真实 API 配额，不要求开发者提供真实密钥；集成测试单独说明配置和成本。
- 存储集成测试使用隔离临时数据，明确清理，不读取或删除开发者已有任务。
- 对话逻辑按改动范围覆盖无效输入、模型失败、超时、取消和会话隔离；流式能力已实现时验证结束、断连和跨分块数据处理。
- 定时任务按实际功能覆盖确认后创建、保存失败、状态变化、执行失败、重试和重复执行边界，不假定未实现的恢复策略已生效。
- 时间相关测试注入可控时钟或明确的参考时间，覆盖本地时区与 UTC 转换，涉及夏令时时验证对应边界；不用长时间真实等待测试计划任务。
- 并发测试使用事件或同步屏障和有界超时，不靠任意 sleep 保证顺序。
- mock 放在被测代码实际查找对象的位置；保留真实接口形状，避免宽松替身隐藏参数和异步用法错误。
- 缺陷修复先用回归测试复现，再验证修复；不删除断言、吞掉异常或永久跳过失败测试。

## 替身与隔离

- mock 尽量使用 `spec`、`spec_set` 或 autospec 检查接口，但不要假设静态签名能验证业务语义。
- 异步依赖使用 `AsyncMock` 或等价异步替身，验证 await 行为而不只是函数被调用；流式结果用异步迭代替身，不替换成普通列表。
- 模拟外部错误时保留异常类别与关键行为，覆盖“外部操作可能成功但响应丢失”，不能只模拟明确未执行的错误。
- fixture 明确作用域及资源所有者，使用临时目录和清理机制；跨用例不得残留环境变量、后台任务、单例或数据库数据。
- 测试取消前等待操作确实开始，结束后等待清理完成，检查没有遗留任务；不只断言产生了超时异常。
- Windows 时区测试先确认 zoneinfo 数据可用，缺数据与业务逻辑失败分别报告，不让所有时间测试悄悄跳过。

先运行受影响测试，再扩大到可用测试集。准确区分单元测试、真实外部服务集成测试与未执行的验证。mock 的具体能力可查阅 [Python 3.10 unittest.mock 文档](https://docs.python.org/3.10/library/unittest.mock.html)。

## 覆盖率任务

仅在明确要求覆盖率测量、覆盖率回归或定位缺口时，使用现有覆盖率工具与新鲜证据；普通回归测试不自动触发全量 coverage。

报告证据对应的代码和测试状态，优先补足调用方可见的错误、取消和生命周期分支，不用只执行代码而没有独立断言的测试刷百分比。只有最终内容未变时才能复用测量，过时报告不能支持当前覆盖率结论。
