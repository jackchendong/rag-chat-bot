# 运行行为探测

## 最小可信实验

- 将问题写成可观测假设：实际入口、输入、预期信号、能推翻判断的结果，以及已知正常对照。
- 先确认静态阅读或已有测试是否足够；只在运行证据有价值时建立探测。
- 在当前解释器和代码中执行真实调用链，不以邻近 helper 成功证明服务、模型或持久化流程成功。
- 记录解释器、工作目录、相关版本及代码状态，不打印全部环境变量或真实凭据。

## 风险与样本

- 安全本地实验可以直接执行。真实模型、数据库变更、外部任务或凭据使用需先明确目的、目标、成本/副作用、环境变量名称及清理方式；超出既有授权时询问用户后再运行。
- 对确定性问题使用单次最小复现；并发、重试、缓存和流式问题按风险选择有限重复，不硬编码所有问题必须运行固定次数。
- 比较场景保持输入、模型参数、输出约束和状态一致，区分冷启动与复用；样本不足时不宣称全面质量或性能等价。
- 设置执行次数、总耗时和输出大小上限；错误诊断也必须脱敏，不能原样打印 SDK 异常或响应正文。

## 矩阵与报告

按需要记录场景、对照、状态隔离、运行次数、实际观察、证据和限制。优先报告意外或负面结果；缺少外部权限或资源时报告未验证，不以 mock 替代真实结论。

一次性探测脚本默认放在任务临时目录而非交付代码，明确保存或清理状态。重复出现且有回归价值的场景，在既有测试体系中转为正式测试；不用临时实验绕过测试或扩展产品范围。
