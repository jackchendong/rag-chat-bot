# 后端项目概览

`app/` 是大模型对话 Demo 的 Python 后端，目标是支持普通对话、通过对话创建定时任务，以及后台调度和执行结果查询。前端位于 `../front/`；浏览器只负责交互和展示，不承担任务调度。

当前已实现账号登录或创建、用户存在性与会话归属校验、会话历史和 FastAPI 多轮对话 `POST /api/chat`，通过 HTTPX 调用 DeepSeek 并返回 SSE。请求头使用 X-User-Id，聊天使用 conversation_id。`main.py` 仅创建应用，配置从 .env 和环境变量加载，后者优先；依赖使用 pip 与 requirements.txt 管理。说明以本目录 README.md 为准，尚未实现正式认证、任务存储、调度和正式测试体系。

本文件适用于 `app/` 及其子目录。规范组织参考 `nodelease`，应用分工参考 fastapi-clean-architecture，并按本 Demo 实际职责精简；不继承参考工程的 Go、Redis 租约、认证或发布约定。

## 环境与依赖

- 当前本地虚拟环境为 `app/.venv`，已检测解释器版本为 Python 3.10.11；在显式升级运行环境之前，代码兼容 Python 3.10，不使用更高版本专属语法或 API。
- 在 `app/` 工作目录下，Windows Python 路径为 `.venv/Scripts/python.exe`，Git Bash 可用 `./.venv/Scripts/python.exe`。不要误用全局解释器。
- `.vscode/settings.json` 用于打开 `app/` 文件夹时选择解释器和 Git Bash，不修改 `.bashrc`、系统 Python 或全局工具配置。
- 新增依赖前检查现有清单，沿用 pip 与 `requirements.txt`，不同时引入多套管理方案，也不为维护文档安装应用依赖。
- 当前使用 `.venv/Scripts/python.exe -m pip install -r requirements.txt` 安装依赖，使用 `.venv/Scripts/python.exe -m uvicorn main:app --reload` 在 `app/` 启动本地服务。
- Web 框架已选定为 FastAPI，模型适配使用 HTTPX；不引入平行框架。数据库、模型 SDK 或调度框架按真实需求选择，并更新依赖和运行文档。
- 不提交 `.venv/`、缓存、密钥、日志或本地运行数据。

## 组织与代码约定

- `backend/application.py`：应用工厂、路由注册、lifespan 与依赖装配；`main.py` 只保留 Uvicorn 入口。
- `backend/api/`：HTTP 路由、Depends 与 SSE 传输；`backend/schemas/`：外部字段校验。
- `backend/services/`：业务编排，仅依赖领域契约，不导入 FastAPI、HTTPX 或供应商实现。
- `backend/domain/`：标准库数据类型、模型网关协议和安全业务错误，不依赖外层实现。
- `backend/providers/`：模型供应商网络适配与数据解析；`backend/core/`：配置加载与校验。
- 数据库采用 MySQL、SQLAlchemy 2.0 和 PyMySQL；db 管理 Session，models 管理 users、conversations、messages 映射，repositories 实现领域存储协议，migrations 与 Alembic 管理版本。分层实现前读取 `.agents/skills/fastapi-architecture/SKILL.md`。
- X-User-Id 必须对应已有用户，所有会话操作校验归属。无密码登录不能防止冒用，不将其描述为正式认证。生成前提交消息和占用标记，生成后提交回答再发送 done；同步数据库操作放在线程池，流式期间不持有长事务。
- 数据库配置从 `.env` 和环境变量加载，密码使用 SecretStr，不打印连接凭据。启动只创建惰性引擎，不自动连接、建表或迁移；迁移由用户手动执行。未明确授权时不连接远程数据库，不运行在线迁移、autogenerate 或探活。
- Session 按请求关闭，事务由业务明确提交；同步 PyMySQL 查询不直接放在异步路由中。数据库会话使用 UTC，ORM 与迁移保持字段、默认值和自动更新时间一致。

- 保持当前实现简单；职责增长后再按需拆分请求入口、业务服务、模型适配、任务调度、持久化、配置和测试，不预建空目录。
- API 层负责输入校验和响应映射，业务层不依赖前端展示逻辑，模型和存储调用保持明确边界。
- 遵循已有代码风格；新增代码默认使用 4 空格缩进、snake_case 函数和变量、PascalCase 类、UPPER_SNAKE_CASE 常量。
- 优先标准库和已有依赖，类型与异常规则见 Python 技能，不为了单一调用增加复杂抽象。
- 不在模块导入时启动服务、调度器、网络请求或执行任务；客户端与后台资源通过明确生命周期创建和关闭。
- 若后续出现包结构，按实际导入方式提供启动命令，不通过临时修改 `sys.path` 绕过包设计。

## 普通对话契约

- 前后端接口路径、字段、错误和流式协议以实际实现及文档为准，修改可见契约时同步协调前端并更新 README。
- 模型凭据仅在服务端读取，不返回给浏览器，不记录到日志；配置缺失应明确失败，不伪装正常回复。
- 外部模型调用设置超时，区分取消、超时、限流和服务错误；重试有界，考虑调用成本及重复副作用。
- 会话和消息归属明确，不将所有用户的对话放入无隔离的全局列表。
- 模型输出是不可信内容，不能直接作为 Python、shell 命令或任意文件操作执行。
- 需要流式输出时明确事件格式、结束与错误语义，处理断连和资源清理；不承诺尚未实现的 SSE 或 WebSocket。

## 定时任务契约

- 区分自然语言任务草稿、用户确认、保存成功和执行成功。模型声称“已创建”不能替代真实存储成功。
- 创建前校验任务内容、执行方式、时间和时区；模糊信息先澄清，不默认采用服务器本地时区。
- 使用带时区的时间表示。对外明确时间格式及 IANA 时区；持久化时保留可恢复的周期规则和时区语义。
- 后台任务不能依赖前端页面存活，也不能仅依赖进程内临时列表声称支持重启恢复。
- 调度器在服务生命周期中显式启动和关闭，开发热重载或多个进程不能无意启动重复调度。
- 引入并行执行时明确任务认领、并发上限、超时、重试和幂等规则；没有保障时不能承诺“恰好一次”。
- 记录可查询的任务状态、执行时间、结果与失败原因；状态枚举及转换以实际接口契约为准。
- 服务重启后的恢复、错过执行时间和重复执行策略必须在实现时确定并写入文档，不能默默猜测。
- 仅执行项目明确支持的任务类型，不把用户输入转换为任意命令，不擅自扩展邮件、短信、RAG 或外部自动化能力。
